# Android preview acceptance

Проверено 18 октября 2026 года. Это результат проверки конкретной сборки,
а не обещание одинакового поведения всех версий Android и прошивок.

## Автоматические проверки

- 20 JVM-тестов: ссылки и общий план маршрутизации.
- Debug lint без замечаний; debug, release и Android test APK собираются.
- 10 instrumented-тестов на API 35: локально arm64, в GitHub Actions x86_64.
- Настоящий JNI TrustTunnel 1.1.7 проверяет настройки; тесты создают TUN,
  заменяют его, проверяют ошибки, хранилище, внешние интенты и IPv6.
- Запуск без action/config extras читает выбранный зашифрованный профиль.
  Этот тест проверяет восстановление настроек, а не планировщик Android.

## Настоящий туннель

Изолированный официальный TrustTunnel endpoint 1.1.0 запущен на macOS,
только на `127.0.0.1:29443`, с временными учётными данными и сертификатом.
Архив `trusttunnel-v1.1.0-macos-universal.tar.gz` проверен по digest релиза:
`126a5688e922ce8f83d4de2d8a2659b3aab97820184d30f2edbecc0ec4a32ae5`.
Клиентский адаптер при этом остаётся 1.1.7: номера релизов сервера и клиента
независимы.

Endpoint экспортировал ссылку `tt://`; приложение показало подтверждение
импорта, сохранило профиль и подключилось с `skip_verification = false` и
закреплённым сертификатом. Подключение через HTTP/2, TLS 1.3.

Трафик прошёл цепочку:

```text
Android shell TCP → Android TUN → TrustTunnel TLS/HTTP2
  → endpoint SOCKS5 forwarding → HTTP test fixture
```

Назначение `198.18.0.42:29881` существует только в SOCKS5 fixture. Получен
`HTTP/1.1 200 OK` с маркером `FREETUNNEL_E2E_OK`; endpoint подтвердил CONNECT
к этому адресу. Это проверка передачи данных через ядро, в отличие от теста,
который только удерживает TLS-сокет. DNS, UDP/HTTP3 и реальные мобильные сети
данным TCP-сценарием не проверяются.

При приостановленном endpoint запрос к публичному IPv4 адресу не получил
ответа через VPN с включённым kill switch. После ручного отключения VPN тот
же адрес ответил HTTP. После возврата endpoint повторное подключение снова
доставило тестовый HTTP-маркер. Намеренно исключённые из профиля маршруты
(в том числе локальная сеть) остаются исключёнными.

Для повторения на отдельном эмуляторе:

1. Скачайте endpoint из [официального релиза](https://github.com/TrustTunnel/TrustTunnel/releases/tag/v1.1.0),
   проверьте digest и создайте временный TLS-сертификат и credentials.
2. Настройте HTTP/2 listener на `127.0.0.1:29443` и
   `[forward_protocol.socks5]` с `address = "127.0.0.1:29880"`,
   `extended_auth = false`; в hosts задайте сертификат и его hostname.
3. SOCKS5 fixture должен принимать CONNECT к `198.18.0.42:29881` и отвечать
   на `GET /qa HTTP/1.1` приведённым HTTP-маркером. Остальные назначения
   отклоняйте; UDP в этом fixture не реализован.
4. Выполните `adb reverse tcp:29443 tcp:29443`, экспортируйте ссылку endpoint
   на `127.0.0.1:29443` с закреплённым сертификатом, импортируйте и подключитесь.
5. Из `adb shell` откройте `toybox nc -w 5 -W 5 198.18.0.42 29881`, отправьте
   HTTP-запрос с `\r\n` и пустой строкой и прочитайте ответ. Держите stdin
   открытым до ответа: закрытие stdin сразу после отправки может завершить nc.
6. Проверьте недоступность публичного назначения при остановленном endpoint,
   затем его доступность после отключения VPN. В конце удалите reverse,
   временный профиль, сертификат и тестовые процессы.

## Завершение процесса и системная защита

После `run-as org.freetunnel.android kill -9 PID` система убирает TUN.
Приложение после повторного открытия показывает «Отключено», старое значение
на диске не используется. При включённых **Always-on + Block connections
without VPN** запрос к тому же публичному адресу блокируется и после смерти
процесса. Ручное подключение снова передаёт HTTP-маркер.

При отдельной полной перезагрузке эмулятора с Always-on Android сам запустил
сервис с `android.net.VpnService`, без конфигурации в extras. После загрузки
и восстановления тестового `adb reverse` выбранный зашифрованный профиль
подключился и доставил HTTP-маркер без нажатия «Подключить».

На проверенном API 35 процесс не перезапустился автоматически в течение
30 секунд. `START_STICKY` оставлен как запрос системе; его нельзя считать
гарантией восстановления, а Always-on — непрерывным watchdog. Система может
запустить VPN при включении Always-on, разблокировке пользователя или обновлении
пакета. Force-stop отдельно запрещает обычное автоматическое возобновление.

Наблюдаемая последовательность согласуется с гонкой в AOSP: удаление TUN
вызывает unbind VPN, обработка ошибки Binder удаляет сервис из списка процесса,
после чего обработчик смерти может уже не запланировать restart. Это объяснение
по исходникам платформы, а не доказательство поведения каждой прошивки:
[VPN interface removal](https://android.googlesource.com/platform/frameworks/base/+/android-15.0.0_r1/services/core/java/com/android/server/connectivity/Vpn.java#2150),
[service unbind / process cleanup](https://android.googlesource.com/platform/frameworks/base/+/android-15.0.0_r1/services/core/java/com/android/server/am/ActiveServices.java#6646),
[START_STICKY contract](https://developer.android.com/reference/android/app/Service#START_STICKY).

Для защиты, когда процесса нет, требуется системная блокировка соединений
без VPN. Приложение не обещает собственную фильтрацию после снятия его TUN.

## Обновление из приложения (ещё не проверено)

Эти шаги требуют настоящего официального релиза и ещё не выполнялись.
Первый возможный прогон — сразу после публикации android-1.0.0, а полный
переход на новую версию — на android-1.0.1.

1. Официальная 1.0.0 на устройстве показывает в настройках «Проверить
   обновления», а не текст о неофициальной сборке. Только это подтверждает,
   что закреплённый сертификат совпадает с настоящим ключом. Debug-сборка
   показывает текст о неофициальной сборке.
2. 1.0.0 → 1.0.1 с включённым VPN: перед установкой появляется
   предупреждение, после обновления VPN поднимается один раз, а в журнале
   одна строка «TrustTunnel: starting connection». То же с Always-on и с
   Always-on + «Блокировать соединения без VPN».
3. В окне установки Android нажать «Домой» и вернуться в приложение;
   «Отмена» оставляет загруженный файл, и нажатие на строку обновления
   («Версия … проверена…» или «Ожидание подтверждения установки Android…»)
   снова открывает окно установки без новой загрузки.
4. В режиме полёта проверка по нажатию показывает сетевую ошибку; загрузка,
   у которой пропала сеть, заканчивается ошибкой и стрелкой ↻ (отменить
   загрузку нельзя).
5. Настройки сохраняют положение прокрутки после возврата в приложение.
6. Проверка при запуске, как у компьютерной версии, без переключателя в
   настройках: при опубликованном android-1.0.1 официальная 1.0.0 через
   пару секунд после запуска показывает точку на вкладке «Настройки» и
   «Доступна версия 1.0.1» в строке обновления, без «Проверка…» и без
   уведомлений. В режиме полёта при запуске ничего не появляется, ошибки
   тоже нет. Повторный запуск в течение 12 часов не обращается к GitHub
   (в журнале прокси нет запроса к api.github.com), а нажатие
   «Проверить обновления» работает всегда.

## Автоматическое переподключение: ещё не проверено

Шаги ниже ещё не выполнялись. Device-тесты в CI вызывают `onStateChanged` и
`onAvailable` напрямую, как это делают ядро и система, но не проверяют передачу
данных через новое ядро на том же TUN. Пройдите их до android-1.0.0 на стенде из
раздела «Настоящий туннель», с включённым kill switch:

1. Остановите endpoint и нажмите на логотип. Ожидается: «Соединение потеряно —
   трафик заблокирован, переподключение…», одно уведомление с «Переподключить»
   и «Отключить VPN», причина в журнале один раз. Пока приложение открыто,
   уведомление приходит без звука и без всплывающего окна. Так же и при отказе
   запуска (например, конфиг с ошибкой): уведомление «VPN отключён» без звука,
   а причина показана плашкой в самом приложении; при свёрнутом приложении
   уведомление со звуком, плашки нет.
2. Запустите endpoint, ничего не нажимая. HTTP-маркер снова приходит не позже
   чем примерно через 30 секунд, уведомление исчезает, в журнале строка
   `Reconnected automatically`.
3. Подключитесь, приостановите endpoint (`kill -STOP`), подождите минуту и
   возобновите (`kill -CONT`). Трафик возвращается без нажатий. Запишите, как:
   ядро восстановилось само («Восстановление соединения…») или через
   заблокированное состояние и автоматические попытки.
4. На телефоне с endpoint в сети (не через `adb reverse`) включите режим полёта,
   нажмите на логотип и подождите больше минуты. После выключения режима полёта
   подключение происходит за несколько секунд, а не через 30.
5. В заблокированном состоянии выключите экран и выполните
   `adb shell dumpsys deviceidle force-idle`. Пока не выполнен
   `adb shell dumpsys deviceidle unforce`, в `adb logcat` нет новых попыток
   подключения ядра.
6. Включите Always-on, выключите сеть и перезагрузите устройство. После загрузки
   включите сеть: VPN подключается, приложение открывать не нужно.
7. Запустите эмулятор с `-dns-server 192.0.2.53`, чтобы DNS не отвечал, укажите
   в `addresses` имя хоста вместо IP и дождитесь заблокированного состояния.
   Нажмите «Отключить VPN» во время попытки: VPN отключается не позже чем
   примерно через 15 секунд, приложение не зависает.
8. В заблокированном состоянии выполните `run-as org.freetunnel.android kill -9 PID`
   и откройте приложение: логотип тусклый, строки под ним нет, уведомление
   «Соединение потеряно — трафик заблокирован» исчезает.

## Android TV: эмулятор проверен, телевизор ещё нет

На 2026-10-29 последний успешный прогон Android CI для исходного коммита
`235ae8a86df737f70a6bfecbea87d8e201821ce8` этой ветки — запуск `40728628229` —
завершил тесты на Android TV API 34 без ошибок. Этот прогон предшествует
регрессионным тестам ошибки сохранения, добавленным после него. `TvDeviceTest`:
124 теста, 0 ошибок, 2 ожидаемых пропуска: перестановка строки пальцем
доступна только на телефоне, а сценарий установки без разрешения запускается
отдельно до выдачи разрешения. Тур сохранил снимки всех экранов для тёмной,
светлой и русской тем; в `index.txt` этих проходов нет `VIOLATION` или
`UNREACHABLE`. Снимки Home, Configs, Split, Settings и Logs на телефоне и TV
сопоставлены вручную с рендерами тех же пяти страниц компьютера в светлой и
тёмной темах. Для desktop-рендеров использованы Qt 6.8.3, `Main.qml`, ресурсы
приложения и существующие тестовые mock-компоненты; окно снято software
renderer в offscreen-режиме. TV снимки приведены к 960×540 dp, телефонные — к
411×683 dp. Сравнение выполнено по структуре, отступам, типографике, цветам и
отсутствию обрезанного содержимого, а не по совпадению пикселей: системная
строка состояния есть только на Android, а fixture-данные и тестовые логи
отличаются. На узком экране чипы Split закономерно переносятся на следующую
строку; существенных дефектов или расхождений стиля не обнаружено.

Снимки и временный desktop harness не входят в репозиторий. Метод проверки:
Qt 6.8.3 и CMake target в `/tmp/ft-desktop-render/` подключают
`tests/ui/MockBackend.cpp`, `MockDesktop.cpp`, `MockShell.cpp`, `UiTheme.cpp`,
`src/app/AppFont.cpp`, `src/app/LogModel.cpp` и `qml.qrc`, задают `currentPage`
0–4 и темы light/dark, затем сохраняют `QQuickWindow::grabWindow()` при
`QT_QPA_PLATFORM=offscreen` и software rendering.

Это проверка эмулятора и снимков, не физического телевизора. Реальный TV
с пультом остаётся непроверенным.

CI запускает device-тесты и на эмуляторе Android TV API 34 (x86): ярлык на
TV-лаунчере, фокус и его вид (как у рабочего стола) на каждом элементе,
сохранение фокуса и прокрутки, окна поверх страницы и «Назад», отсутствующие
экраны, приём ссылки и файла по сети эмулятора.
Те же прогоны сохраняют снимок каждого экрана (`UiTourDeviceTest`: тёмная,
светлая и русская темы; на телефоне ещё два прохода касаниями) в артефактах
`android-device-results` и `android-tv-device-results`: смотрите их до шагов
ниже, как описано в шаге 45.
Эмулятор не заменяет настоящий телевизор и пульт. Пройдите шаги ниже до
первого релиза с поддержкой TV на Google TV
(Chromecast with Google TV) и на приставке с Android TV 9–11, по возможности
и на Fire TV:

1. Установите APK. На лаунчере есть баннер FreeTunnel, приложение открывается
   с него, фокус на логотипе.
2. Только пультом пройдите все пять вкладок и все окна: меню «+»,
   редактор, удаление, режим, выбор приложений, тема. Каждый
   элемент достижим стрелками, фокус виден с дивана и в тёмной, и в светлой
   теме, и это то, что компьютерная версия показывает под курсором, без кольца
   и без сплошной акцентной заливки: вкладка и строка заливаются цветом
   поверхности (вкладка ещё растёт до 1.08), ссылка и подпись «DE ▾» на «Главной»
   меняют цвет и подчёркиваются (только слова, а не ширину экрана), значение
   выпадающего списка и стрелка «←» светлеют, чип светлее, кнопка принимает
   цвет наведения, у крестика на плашке правила крестик краснеет, у поля
   ввода рамка становится акцентной; у переключателя заливается его строка, не
   ободок вокруг ползунка; логотип на «Главной» увеличен до 1.05 без плитки за
   ним. Отметьте всё, что с дивана найти трудно. Системных диалогов нет: все
   окна нарисованы приложением, «Назад» закрывает окно, а не страницу под ним,
   а фокус возвращается на то, что окно открыло. Кнопка OK пульта нажимает
   элемент; отметьте пульты, которые шлют
   `KEYCODE_ENTER` вместо `DPAD_CENTER`. Редактор открывается с фокусом на
   имени; «Вверх» и «Вниз» уходят из однострочного поля к соседнему элементу,
   а после «Сохранить» с ошибкой в форме фокус остаётся на «Сохранить».
   Отметьте, открывается ли при этом клавиатура сама.
3. Пинг, выбор и удаление конфигурации, подключение и отключение, проверка
   обновлений в настройках не сбрасывают фокус на вкладки и не прокручивают
   страницу к началу. После удаления фокус на соседней конфигурации.
4. «Назад» с любой вкладки, в том числе с фокусом на самой вкладке, ведёт на
   «Главную» с фокусом на логотипе, с «Главной» выходит
   из приложения.
5. Содержимое не обрезано краями экрана, в том числе на старом телевизоре
   с overscan. Журнал прокручивается стрелками.
6. Подключение: появляется системный запрос VPN (или сообщение, что его на
   этом устройстве нет), VPN подключается, kill switch блокирует трафик при
   остановленном endpoint: на «Главной» под логотипом «Подключение…» (как у
   компьютерной версии при переподключении, обычным цветом, а не
   предупреждающим), логотип пульсирует и в фокусе, ссылки «Переподключить»
   на экране нет; нажатие на логотип отключает VPN. Уведомление при этом
   остаётся с «Переподключить» и «Отключить VPN».
7. «Из файла…»: открывается выбор файлов или появляется сообщение, что его
   нет, с подсказкой про «Получить с телефона»; приложение не закрывается.
   «Создать новый…»: форма, поля которой заполняются с клавиатуры
   приложения Google TV на телефоне, пароль показан точками; «Из файла…»
   у сертификата открывает выбор файлов или говорит, что его нет.
8. В настройках ничего нет про постоянный VPN и параметры VPN Android, как
   и у компьютерной версии (как включить, написано в README, раздел
   «Always-on VPN and Block connections without VPN»).
9. В выборе приложений для раздельного туннелирования есть приложения,
   у которых есть только TV-ярлык (например, YouTube для TV).
10. Устройство с 32-битным ARM (большинство приставок): VPN подключается,
    то есть библиотека armeabi-v7a загружается.
11. Меню «+» на «Конфигах» → первым пунктом «Получить с телефона»: QR-код
    на белой плитке и адрес, под ними короткая подсказка в две фразы, всё по
    центру, кнопки нет, фокус на стрелке «←», экран не гаснет, пока окно
    открыто. Отсканируйте код камерой Android
    (Google Lens) и откройте страницу в Chrome, камерой iPhone — в Safari,
    а с ноутбука введите адрес в браузере. Вставьте ссылку tt:// и нажмите
    «Отправить на телевизор»: на телефоне «Отправлено… Ниже можно отправить
    ещё» и та же форма снова, на телевизоре подтверждение с сервером
    и строкой «Отправлено с» и адресом телефона, а окно «Получить с телефона»
    остаётся открытым под вопросом, со строкой «Получено: 1». Не отвечая,
    отправьте с той же страницы вторую ссылку (другой сервер): на телефоне
    снова «Отправлено», на телевизоре «Получено: 2», а вопрос на экране
    по-прежнему о первой. Конфигурации появляются только после
    «Импортировать»; вопросы идут по очереди, в порядке отправки (после ответа
    на первый появляется вопрос о второй), «Отмена» на втором ничего не
    добавляет и окно не закрывает. После «Импортировать» всплывает
    «Конфиг добавлен: …», а страница не меняется. Стрелка «←» (и «Назад»)
    закрывает окно и порт. Отметьте, открывается ли страница сразу или браузер сначала
    предупреждает об HTTP, и не было ли паузы перед страницей или перед
    «Отправлено».
12. То же с TOML-файлом, вставленным на странице текстом.
13. Выбор файла вместо вставки. Положите на телефон TOML-файл без ключа
    `name` (например `home.toml`) и текстовый файл, в котором только ссылка
    tt:// (например `link.txt`). На странице нажмите поле выбора файла
    и выберите TOML-файл: в Chrome на Android (из «Загрузок» и из Google
    Диска), в Safari на iPhone (из «Файлов», в том числе из iCloud Drive), на
    ноутбуке в Chrome и Firefox (и в Safari на Mac, если есть). На телефоне
    «Отправлено», на телевизоре подтверждение с именем файла («home.toml»),
    сервером и строкой «Отправлено с». Повторите с `link.txt`: конфигурация
    называется по ссылке, а не по файлу. Повторите с TOML-файлом с русским
    именем (например `Дом.toml`): в подтверждении нет фразы о похожих символах
    разных алфавитов. Отметьте, не затенены ли в выборе файлов файлы `.toml`.
14. Нажмите «Отправить на телевизор», ничего не вставив и не выбрав; затем
    вставьте ссылку и выберите файл сразу; затем выберите фотографию. Каждый
    раз на телефоне «Телевизор ничего не принял» и форма снова, телевизор ждёт
    дальше, и отправка правильного файла с этой же страницы проходит. Затем
    по Wi-Fi выберите фотографию с камеры телефона (больше 512 КиБ): на
    телефоне та же форма с фразой, что это больше 512 КиБ, а не ошибка
    соединения; отметьте браузеры, где вместо неё ошибка. Затем выберите видео
    на десятки мегабайт: телевизор дочитывает не дольше 2 секунд, так что
    ошибка соединения здесь допустима. Телевизор каждый раз ждёт дальше.
15. Откройте QR-код сторонним сканером QR-кодов со своим встроенным браузером
    (не камерой и не Google Lens). Отметьте, открывается ли там выбор файла;
    если нет, вставка ссылки там работает, а в Chrome выбор файла работает.
16. Измените в адресе одну букву кода: страница открывается, отправка
    показывает «Неверный код». После третьей такой отправки телевизор
    сообщает, что приём остановлен, и страница больше не открывается.
    Неверные коды складываются за весь сеанс: неверный код, затем правильная
    отправка, затем ещё два неверных — тоже остановка. Что пришло до
    остановки, телевизор всё равно спрашивает по очереди.
17. Ничего не отправляйте 5 минут: телевизор сообщает, что за 5 минут
    ничего не пришло, заставка за это время не включается. Повторите,
    отправив что-нибудь на первой и на второй минуте: отправки время
    не продлевают, через 5 минут после открытия окна приём прекращается
    («Приём остановлен через 5 минут…»), а вопросы о пришедшем остаются.
    Откройте приём снова, отправьте три текста и нажмите Home: приём
    прекращается, страница больше не открывается, а вопрос, который был
    на экране, остаётся; ожидавшие своей очереди пропадают.
18. С включённым VPN на телефоне, по мобильной сети и в гостевой сети
    с изоляцией клиентов страница не открывается (так и должно быть; на
    карточке телевизора об этом нет ни слова, подсказка короткая, а совет
    «выключите VPN на телефоне» есть только в README). Выключите VPN на
    телефоне: страница открывается. С подключённым VPN FreeTunnel на
    телевизоре страница открывается. На странице на телефоне по-прежнему
    сказано, что текст идёт по сети без шифрования и отправлять его стоит только
    в доверенной сети.
19. Телевизор только с Ethernet и телевизор с Ethernet и Wi-Fi сразу: адрес
    на карточке из сети, которой телевизор пользуется, и телефон её открывает.
20. Настройки → Общие → Тема: «Система» (по умолчанию) следует за настройкой
    устройства, «Светлая» и «Тёмная» от неё не зависят. Отметьте, какую тему
    показывает ваш телевизор в режиме «Система»: некоторые телевизоры
    сообщают светлую тему, и приложение тогда откроется светлым. После выбора
    темы пультом фокус остаётся на строке «Тема».
21. Редактор: поля как у компьютерной версии (имя, хост, адреса, логин и пароль
    в одной строке, протокол и DNS, SNI и client random, профиль, три
    переключателя, сертификат, «Отмена» и «Сохранить» в конце прокручиваемой
    формы). Правка конфига, у которого есть свои маршруты или правила (файл
    провайдера, в том числе с endpoint в виде inline-таблицы): после
    «Сохранить» они на месте, а если файл нельзя записать, ничего не потеряв,
    сохранение отклонено сообщением и конфиг не изменён. Пустое имя берётся
    из хоста (не длиннее 50 символов); набранное имя длиннее 50 символов
    отклонено: «Слишком длинное имя: не больше 50 символов». Пароль — кружки ●
    шрифтом остальных полей, как у компьютерной версии, и ни один набранный
    символ не показывается открытым, даже на мгновение (при включённой в системе
    настройке «Показывать пароли»). В заполненном поле каретка стоит в конце
    текста (в том числе когда поле получает фокус пультом или клавиатурой).
    «Из файла…» у сертификата: пустой файл и файл
    больше 1 МБ сообщают об этом. Ошибки формы: «Заполните имя хоста, адрес, логин и пароль», адрес без
    порта, DNS не IP, client random не hex, сертификат без BEGIN CERTIFICATE.
    «Назад», стрелка и «Отмена» после ввода спрашивают «Закрыть без
    сохранения?» («Не сохранять» красная), без ввода закрывают сразу; «Отмена»
    в вопросе оставляет набранное. Фокус стартует на имени. На телефоне
    клавиатура не закрывает «Сохранить»: карточка уменьшается и прокручивается
    к полю с кареткой; поворот экрана не закрывает редактор и не стирает
    набранное. Со снимком экрана или в списке недавних открытый редактор
    чёрный. Проверьте на Android 15 (край в край) и на более старом.
22. Импорт, имя которого уже есть в списке: «Отмена», «Добавить копию»
    и «Заменить». «Заменить» оставляет конфиг на его месте, «Добавить копию»
    добавляет второй. Красная кнопка и «Добавить копию» не откликаются первые
    0,4 с; зажатый или удвоенный OK пульта вопрос не подтверждает. Вопросы
    идут по очереди, ни один не вытесняет другой.
23. Выбор приложения: в фокусе поиск (на телефоне поднимается клавиатура, на
    телевизоре «Вниз» переходит к первой строке). Поле для приложения на
    «Маршрутизации» под списком приложений: набранное имя показывает
    подходящие приложения над полем (три строки, остальные прокручиваются),
    Enter или касание добавляет выделенное, «Вверх»/«Вниз» двигают выделение,
    «Назад» сначала убирает список. Пока приложения ищутся, окно
    говорит об этом, а телевизор с сотней приложений не подвисает. Одно
    нажатие добавляет одно приложение и закрывает окно. Поиск находит
    и по названию, и по имени пакета.
24. Уведомления: длинный отказ (подписка, ядро новее) читается целиком, исчезает
    сам и убирается нажатием; поверх открытого окна он наверху. Не удаётся
    прочитать хранилище (ошибка хранилища на устройстве с заблокированными
    ключами): янтарная плашка вверху «Конфигов» и в «Настройках».
25. Темы: на открытых окнах (редактор, подтверждения, выбор приложения,
    «Получить с телефона») в светлой и тёмной теме текст читается,
    красная кнопка всегда красная с белой подписью (в фокусе темнее),
    «Сохранить» акцентная (в фокусе темнее), остальные кнопки нейтральные
    (в фокусе светлее); так же с пультом и без него.
26. Очередь: отправьте со страницы 10 текстов подряд, не отвечая на вопросы
    (можно один и тот же): на телевизоре «Получено: 10». Одиннадцатая
    отправка, и следующие, показывает на телефоне «На телевизоре уже
    10 ожидают подтверждения…» и ту же форму; это не неверный код: после
    нескольких таких отправок телевизор по-прежнему слушает. Ответьте на один
    вопрос («Отмена»): следующая отправка проходит. Закройте окно стрелкой
    «←», пока вопросы в очереди: страница больше не открывается, а вопросы продолжают
    появляться по одному.
27. Страница на телефоне в светлой и в тёмной теме телефона (Safari на iPhone,
    Chrome на Android, по возможности ноутбук): цвета и шрифт как у
    приложения, а не системные: серые поля с тонкой рамкой, у поля вставки
    в фокусе рамка меняется, кнопка выбора файла нейтральная, «Отправить на
    телевизор» без системной синей заливки, заметки мелкие и бледные. Текст
    в поле вставки моноширинный, 16 пикселей (у поля сертификата на
    компьютере 12; здесь 16, чтобы Safari на iPhone не увеличивал страницу
    при касании поля): поле не увеличивает страницу при касании на iPhone.
    Над формой уведомление на страницах «Отправлено», «Телевизор уже…»
    и «Телевизор ничего не принял». Отметьте, где кнопка выбора файла
    осталась системной.
28. «Главная»: логотип единственная кнопка подключения (кнопки «Подключить» и
    зелёного слова «Подключено» нет). Нажатие или OK подключает, во время
    подключения логотип пульсирует и под ним «Подключение…», у подключённого
    под ним время `ЧЧ:ММ:СС`, которое идёт без дёрганья страницы и фокуса; при
    «Отключении…» пульс снова. Логотип тусклый без сеанса (0.5), средний
    в пути (0.7), яркий подключённым (1.0), и без сеанса он ниже на 12 dp.
    Двойное нажатие считается за одно. Без конфигов нажатие на логотип, на
    «Добавить конфиг» и на «+» открывает «Конфиги» с меню. Подключение не
    показывает уведомлений («Проверка конфигурации…», «Применяются настройки
    маршрутизации»): ход виден по логотипу и строке под ним. Отметьте, виден ли
    на телевизоре фокус на логотипе (он увеличен до 1.05 без плитки за ним, и
    пульсация идёт поверх).
29. Выбор сервера прямо на «Главной»: стрелками на «DE ▾», OK. Список
    открывается под ним, виден по три строки (остальные прокручиваются),
    выбранный конфиг в акценте и с фокусом. OK на другой строке закрывает
    список, меняет подпись и, если VPN включён, переподключает к новому
    серверу. «Назад» и касание вне списка закрывают его, а не уходят
    с «Главной». «Конфиг добавлен: …» после импорта на «Главной» стоит между
    выбором сервера и плитками скорости.
30. «Конфиги»: у строки иконки экспорта, правки и удаления, текстовых кнопок
    нет. Пультом: вправо от строки экспорт, правка, удаление, влево обратно,
    вниз следующая строка. У выбранного конфига «подключён» (зелёным), «подключение…»
    на пути к нему (и при заблокированном трафике), при отключении значка нет.
    Значок пинга: «…», затем «N мс» или «—»; один недоступный сервер не
    задерживает остальные дольше 3 с. «Удалить конфиг «…»?» с красной
    «Удалить».
31. Экспорт: «Скопировать deep-link» и вставка в другом приложении
    («Вставить из буфера» на «Конфигах» другого устройства): тот же сервер, то
    же имя; на Android 13 и новее клавиатура не показывает ссылку в истории
    буфера обмена. «Экспорт .toml…» открывает системный выбор места и
    сохраняет файл; на телевизоре без такого экрана сообщение. Оба сообщения
    говорят, что в файле и в ссылке пароль.
32. Телефон: нажмите на строку конфига и удерживайте, затем тяните вверх или
    вниз: остальные расступаются, после отпускания порядок сохранён (виден
    и после перезапуска), выбранный конфиг остался выбранным. Обычное касание
    выбирает конфиг и не меняет порядок. На телевизоре строки не перемещаются.
33. Плитки скорости: ↓ и ↑ в МБ/с растут при загрузке и отдаче по VPN и 0.0
    без подключения. Это счётчики самого приложения, то есть и служебный
    трафик туннеля, а не точная скорость пользовательских данных. Запишите,
    на каких устройствах счётчиков нет (там 0.0 всегда).
34. «Раздельный туннель»: сверху переключатель «Раздельное туннелирование»,
    «Режим» (только значение и ▾), затем «Профиль» с чипами: «По умолчанию»
    без крестика и свои с крестиком, выбранный для правки залит акцентом без
    галочки (с пультом и без, как у компьютерной). Чип выбирает
    профиль для правки, VPN при этом не переподключается. «+» открывает поле
    «имя профиля и Enter» (не больше 16 символов): Enter добавляет и выбирает
    профиль, Escape, «Назад» и уход стрелкой убирают поле, и ничего не
    добавляется. Имя, отличающееся только регистром («work» при «Work»),
    отклоняется фразой «Профиль «Work» уже существует». Крестик профиля
    спрашивает «Удалить профиль «…»?»; конфиги этого профиля после удаления
    используют «По умолчанию». Пультом: вправо от чипа его крестик, влево
    обратно, вправо от крестика следующий чип.
35. Правила: «Сайты РФ» добавляет список (общий с компьютерной версией)
    в редактируемый профиль без повторов; второй раз ничего. «Очистить»
    (красная, только когда правила есть) спрашивает «Очистить все домены?».
    Крестик правила убирает его сразу. В поле доменов запятые, пробелы и `;`
    разделяют; допустимые добавляются, недопустимые названы («Неверный домен
    или подсеть: …»), а «0.0.0.0/0» и «*.1.2.3.4» с объяснением; если не
    добавлено ничего, набранное остаётся. «Приложения»: «Выбрать…» добавляет
    одно приложение в профиль, «Очистить» спрашивает; удалённое с устройства
    приложение видно по имени пакета и убирается крестиком. Полей для ввода
    приложения нет.
36. Профиль конфига: в редакторе поле «Профиль раздельного туннеля» (список
    профилей, текущий с галочкой). Одно изменение профиля уже считается
    изменением: «Отмена» спрашивает. Выберите конфиг, использующий другой
    профиль, и подключитесь: маршрутизация по правилам этого профиля, так же
    при запуске из плитки и при постоянном VPN (Always-on). Правка правил
    профиля выбранного конфига при включённом VPN переподключает, правка
    другого профиля нет.
37. Обновление с 1.0.0 (установите поверх с настроенными списками): правила
    и приложения теперь в «По умолчанию», по алфавиту, режим и переключатель
    прежние. Чистая установка: переключатель включён, режим «Без VPN»,
    в «По умолчанию» список для России. Возврат на 1.0.0 (установка поверх
    более старой версией возможна не везде, проверьте там, где можно): в его
    списках правила профиля выбранного конфига.
38. Уведомления на странице: «Через VPN» без правил — фраза про профиль
    и конфиг по их именам, «Через VPN» с приложениями и доменами вместе
    — фраза, что Android не может направить оба сразу; без конфигов — фраза
    «Добавьте правило…». В режиме «Без VPN» или при выключенном
    переключателе уведомлений нет. Правила самого конфига перечислены через
    запятую.
39. «Настройки» как у компьютерной версии (сверьте с её снимками): поля 18 по бокам,
    подписи разделов обычным шрифтом, линии только между строками «Основного»,
    после «Безопасности» «Исключённые маршруты», «Логирование», «Обслуживание»
    и внизу по центру «FreeTunnel 1.0.0 · Ядро TrustTunnel 1.1.7», только эти
    две ссылки (экрана лицензий нет, как и у компьютерной версии: уведомления
    лежат файлами в APK). Раздела «О приложении» нет. На телевизоре стрелки
    проходят все строки.
40. «Язык»: «Русский» и «English» названы на своих языках. Выбор перезапускает
    экран на «Настройках» уже на новом языке; уведомление VPN, плитка быстрых
    настроек и страница «Отправить в FreeTunnel» (откройте «Получить с телефона»)
    тоже на нём. Проверьте и Android 8–12 (язык задаёт само приложение), и
    Android 13+ (в системных настройках приложения те же два языка; выбор там
    меняет язык приложения, а строка «Язык» показывает тот, на котором оно
    говорит). Пока язык не выбран, приложение говорит на языке устройства.
41. «Исключённые маршруты»: у новой установки 10.0.0.0/8, 100.64.0.0/10,
    169.254.0.0/16, 172.16.0.0/12, 192.0.0.0/24, 192.168.0.0/16 и
    255.255.255.255/32 (как у компьютерной). Несколько подсетей сразу через
    пробел, запятую или «;»; адрес без длины становится /32; не подсеть
    называется по имени, а «0.0.0.0/0» отклоняется с объяснением. «По умолчанию»
    и «Очистить» сначала спрашивают («Заменить», «Очистить»), крестик убирает
    сразу. Подключённый VPN после изменения пересобирается молча. С подключённым
    VPN хост в локальной сети (192.168.x.x) отвечает мимо туннеля, а после
    «Очистить» и переподключения его трафик идёт через туннель. Обновление
    с превью: маршруты по умолчанию появляются и у тех, кто ничего не
    настраивал (в превью их не было), как у компьютерной, где без
    сохранённого списка действуют значения по умолчанию.
42. «Обслуживание», строка обновления на официальной сборке: «Проверить
    обновления» и версия; во время проверки три прыгающих точки, нажатие ничего
    не делает, а фокус пульта остаётся на строке; «Доступна версия X» со стрелкой
    вниз, которая в фокусе (или под курсором мыши) загибается в ↻; загрузка со
    стрелкой, которая вращается, нажатие ничего не делает (остановить загрузку
    нельзя, как и в компьютерной версии), по окончании стрелка плавно
    возвращается; загруженное обновление: «Установить» через вопрос при
    включённом VPN; ошибка проверки «Не удалось проверить обновления: …» со
    стрелкой ↻, которая в фокусе наклоняется. Точка на вкладке «Настройки»
    пока есть обновление. Слова, кроме «Версия … проверена…» и «Ожидание
    подтверждения установки Android…» (они говорят «нажмите на эту строку»;
    кнопки «Установить обновление» на экране нет), те же, что у компьютерной.
43. Подвал: «FreeTunnel…» и «Ядро TrustTunnel…» открывают страницы в браузере;
    на телевизоре без браузера появляется уведомление, приложение не закрывается.
44. «Журнал»: строки «ЧЧ:ММ:СС УРОВЕНЬ сообщение»; при подключении появляются
    строки о каждом соединении (куда оно пошло, через туннель или мимо), и они
    добавляются без нажатий (раз в секунду), не сбивая прокрутку, пока «Авто-
    прокрутка» включена; выключите её, прокрутите вверх: новые строки не двигают
    окно; включите: оно уходит в конец. «Очистить» очищает сразу без вопроса и
    показывает «Логи появятся после подключения». «Копировать» говорит «Лог
    скопирован», в другом приложении вставляется то же, что на экране (на
    Android 13+ превью буфера скрыто). Выключите «Включить логирование»:
    на странице «Логирование выключено.» и «Включить», новые строки не
    пишутся. Выделение текста на телефоне не сбрасывается живым обновлением.
    На телевизоре текст не выделяется, «Вниз» с «Копировать» ведёт в окно
    журнала, стрелки его прокручивают, а в конце — на «Авто-прокрутку». Строки
    журнала от прошлой версии (число и текст) показываются как были.

45. Снимки интерфейса. В последнем прогоне Android CI скачайте артефакты
    `android-device-results` (телефон) и `android-tv-device-results` (телевизор).
    В `uitour/<phone|tv>-<проход>/` лежат `NN-имя.png` по одному на экран,
    `index.txt` (что на каком снимке; строки `UNREACHABLE`: состояние, до
    которого тур не добрался, оно не рисуется; строки `VIOLATION`: найденное
    проверками) и `index.html` с миниатюрами; проходы `dark`, `light`,
    `dark-ru`, на телефоне ещё `touch-dark` и `touch-light`. Страницы, которые
    телевизор отдаёт телефону, лежат в `<phone|tv>-phone-pages/` как `.html` на
    обоих языках, в светлой и тёмной теме. Сравните с компьютерной версией,
    запущенной рядом в той же теме: цвета, радиусы, шрифт, размеры и порядок на
    «Главной», «Конфигах», «Раздельном туннеле», «Настройках» и «Журнале»,
    окна, меню, подтверждения и редактор; фокус, показанный на снимках
    пультового прохода, везде такой, как наведение курсора на компьютерной:
    ни кольца, ни акцентной заливки, ни заливки поперёк экрана. Снимок
    эмулятора не заменяет телевизор: шрифт и поля по
    краям на нём иные, их сверяйте с настоящим экраном. Отдельно отметьте
    состояния из `UNREACHABLE` и всё из `VIOLATION`.
46. Фокус с дивана, в обеих темах. С расстояния 3–4 м, пультом, в тёмной
    и в светлой теме: на каждой из пяти страниц и в каждом окне (меню «+»,
    редактор, подтверждение, выбор приложения, «Получить с телефона»)
    фокус находится за секунду, а выбранный пункт (вкладка, профиль, конфиг,
    пункт списка) отличается от сфокусированного (выбранное залито акцентом
    или написано им, сфокусированное чуть светлее фона, подчёркнуто или
    увеличено). Запишите, на каких телевизорах заливка поверхности (#262626
    на #181818 в тёмной, #e2e2e2 на #ececec в светлой теме) или смена цвета
    ссылки почти не видна: это цена того, что фокус не чужое кольцо, а вид
    наведения компьютерной; если она неприемлема, запасной вариант вынести
    на решение (например, масштаб 1.08 всем строкам), но не возвращать кольцо.
    Отдельно пройдите страницы с лампой или окном за спиной: блики на стекле не
    должны быть единственным, что видно.
47. Список серверов на «Главной», с дивана: 5 и более конфигов, виден по три
    строки, остальные прокручиваются стрелками, и прокрутка не теряет фокус;
    выбранный конфиг (акцентный текст) отличим от строки в фокусе (заливка
    поверхности), когда это разные строки. OK на другом сервере при включённом VPN
    переподключает, подпись «DE ▾» меняется, фокус возвращается на неё,
    «Назад» закрывает список. В светлой теме то же.
48. Несколько отправок с телефонов, в светлой и в тёмной теме телефона:
    iPhone (Safari) и Android (Chrome), четыре сочетания. В каждом: три
    отправки подряд с одной открытой страницы (после «Отправлено» форма снова,
    без нового открытия адреса); кнопка браузера «Назад» после отправки не
    показывает старое «Отправлено» вместо формы, а если показывает, форма
    работает; обновление страницы «Отправлено» отправляет текст ещё раз
    (браузер спросит) и на телевизоре появляется ещё один вопрос, как задумано.
    Одиннадцатая отправка при десяти ожидающих показывает страницу «На
    телевизоре уже 10 ожидают…» с формой под уведомлением, читаемую в обеих
    темах, а телевизор слушает по-прежнему; неверный код показывает страницу
    без формы. Шрифт, поля, кнопка выбора файла и кнопка отправки соответствуют
    приложению (шаг 27), в Safari тоже.
49. Данные превью. Поставьте превью 0.9.0, выберите в нём тему (светлую, затем
    тёмную), введите правила и приложения раздельного туннеля, два-три конфига,
    затем установите эту сборку поверх. «Тема» показывает выбранную в превью
    («Светлая» или «Тёмная», не «Система»); правила и приложения превью
    оказались в профиле «По умолчанию», по алфавиту, режим и переключатель
    прежние; конфиги на месте и используют «По умолчанию»; плитка быстрых
    настроек и Always-on собирают сеанс по правилам этого профиля;
    «Исключённые маршруты» получили значения по умолчанию (в превью их не
    было, шаг 41). Свежая установка тем же APK: профиль «По умолчанию» уже
    со списком для России и переключатель включён.
50. Экспорт и «Заменить». На одном устройстве скопируйте deep-link конфига
    (иконка экспорта). На другом создайте на «Раздельном туннеле» профиль
    «Work» и выберите его в редакторе конфига с таким же именем, затем
    вставьте ссылку из буфера на «Конфигах»: вопрос «… уже существует» с
    «Отмена», «Добавить копию» и красной «Заменить». «Заменить» оставляет конфиг
    на прежнем месте и с прежним профилем «Work» (ссылка профиля не несёт),
    и если он выбран при включённом VPN, переподключает; «Добавить копию»
    добавляет второй, с «По умолчанию». Красная кнопка и «Добавить копию» не
    откликаются первые 0,4 с. «Экспорт .toml…» и импорт этого файла («Из
    файла…») дают тот же конфиг; оба сообщения об экспорте напоминают про
    пароль.

## Подпись и публикация

Исторический прогон APK из форка не определяет подпись официального проекта.
Debug APK проверялся через `apksigner verify` (v2); release-подпись остаётся
параметризованной четырьмя переменными окружения, описанными в README.
Без них доступна unsigned release или debug-сборка. Keystore и пароли не входят
в исходники. Официальные Android-сборки и ключ подписи предоставляет CI
`dimmmmmmmer/freetunnel` после мержа; совместимость с подписью форка не требуется.
